# 自由衣物高斯逐帧运输

`FreeClothingTransport` 将参考帧的自由高斯中心、完整协方差和 SH 观察方向同步变换到指定帧。支撑三角只定义运动；高斯可以保留离人体表面的自由偏移。

本模块是可微的 CPU 接口，尚未接入训练器或渲染器。合成测试通过只说明接口及计算链符合约定，不代表真实人像重建质量通过。

## Git 安装与验证

使用现有 Python 3.10 环境，验证版本为 NumPy 1.26.4、Torch 2.7.1。以下 Linux Bash 命令从独立分支检出到新目录并执行 CPU 测试；无需上传代码或下载人体权重。环境默认取 `~/.local/share/smpl-x/env-cu128`，兼容已有的 `shuolee-portrait/env-cu128`；其他路径可先设置 `SMPLX_ENV_DIR`。

```bash
bash -c 'set -eu; test ! -e "$HOME/smpl-x-free-clothing"; git clone --depth 1 --filter=blob:none --no-checkout --branch smplx/free-clothing-transport-123 https://github.com/lizuoshuo-lab/shuolee-portrait.git "$HOME/smpl-x-free-clothing"; cd "$HOME/smpl-x-free-clothing"; git sparse-checkout init --cone; git checkout; git sparse-checkout set src scripts tests docs; CHECK_PY="${SMPLX_ENV_DIR:-$HOME/.local/share/smpl-x/env-cu128}/bin/python"; if [ ! -x "$CHECK_PY" ] && [ -z "${SMPLX_ENV_DIR:-}" ]; then CHECK_PY="$HOME/.local/share/shuolee-portrait/env-cu128/bin/python"; fi; test -x "$CHECK_PY"; export CUDA_VISIBLE_DEVICES=""; mkdir -p test-results; git rev-parse HEAD; "$CHECK_PY" -s -B tests/test_free_clothing_transport.py --report test-results/free-clothing-transport-cpu.json'
```

预期 25 项测试通过，退出码为 0。结果保存在 `test-results/free-clothing-transport-cpu.json`。测试使用完整仓库中的既有 SH 工具，不能只复制新增模块与测试文件运行。已有目标目录时命令停止，避免覆盖工作。

在检出目录使用同一环境执行完整 CPU 回归：

```bash
CUDA_VISIBLE_DEVICES='' python -s -B -m unittest discover -s tests -p 'test_*.py'
```

独立 CI 环境使用 `requirements-test.txt` 中固定的 CPU Torch 依赖。测试报告和临时数据不提交到 Git。

## 输入和输出

构造 `FreeClothingTransport` 时显式提供：

- `frame_ids`、`reference_frame_id`、同拓扑的 `vertices_world` 和 `faces`。
- `gaussian_ids` 与每个高斯固定的 `motion_support_triangle_ids`。调用必须保持相同身份和顺序。
- `frame_source_sha256`，完整覆盖帧身份。这是来源声明，模块本身不读取或核验原始视频。
- `translation_unit='meters'`。所有空间输入必须处于一致坐标与单位；模块不估计物理尺度。

`transport_numpy(...)` 和 `transport_torch(...)` 接收帧身份、参考世界中心、完整正定协方差、当前相机中心及高斯身份。返回运输后的中心、协方差、参考观察方向、旋转、尺度及支撑三角残差。

NumPy 路径使用 float64。Torch 路径接受 CPU float32/float64，保持输入精度以及中心、协方差的自动微分；局部关闭 CPU autocast，返回后恢复调用者状态。内部张量固定创建于 CPU，不随环境默认设备变化。

## 运动约定

参考帧严格恒等。其他帧用三角有向基得到旋转 `Q`，面积比平方根得到尺度 `a`；中心采用 `a Q (x - c_ref) + c_frame`，完整协方差采用 `a² Q Σ Qᵀ`。一般剪切不能由相似变换精确表示，`support_vertex_residual` 保留映射三角与目标三角的差异，定义为三个顶点距离的 RMS 除以目标三角面积平方根。

SH 方向取相机指向当前高斯的单位方向，再通过 `Qᵀ` 旋回参考方向。中心、协方差和观察方向必须使用同一次帧选择；不能只移动中心或只保留协方差对角。

合法 180° 旋转保留。退化三角、身份错序、非对称或非正定协方差、运输后协方差下溢均报明确错误。接口不通过添加 epsilon 或对称化掩盖无效输入。

支撑映射固定，不自动寻找最近三角，也不设置每面高斯配额。克隆、分裂或裁点后，调用方必须显式重建高斯身份与支撑映射。

## 保存与读取

`save(path.json)` 写入 JSON 和同名 NPZ，要求父目录存在并拒绝覆盖。`load()` 禁用 pickle，检查载荷及数组 SHA256、字段集合与身份信息，拒绝重复 NPZ 字段和损坏的 ZIP 校验数据。加载后 `assert_unchanged()` 可验证文件未被修改。

保存内容仅含几何和支撑约定，不包含可学习高斯参数或优化器状态。

## 验证范围

25 项合成控制包含身份与来源绑定、参考恒等、自由偏移、180° 旋转、剪切残差、完整协方差、SH 方向、float32/float64 梯度、序列化以及 CPU 环境行为。

两个尺度控制验证不同性质：

- 同时缩放所有世界长度、相机外参平移、网格、自由中心，并将协方差乘尺度平方，验证像素位置、投影协方差和 SH 方向不变。
- 改变相机平移并从相机空间重建各帧姿态，验证完整姿态补偿链自洽；省略运输的负例应产生明显像素误差。

这些性质不能证明相机外参正确或真实尺度已标定。未知物理米制本身不排除所有相对重建；本接口要求调用方声明并保持一致的单位。真实人物的材料对应、相机、逐帧姿态和渲染质量仍需独立验证，输出中的 `training_admitted`、`physical_quality_accepted` 与 `renderer_connected` 保持 false。
