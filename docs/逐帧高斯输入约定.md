# 逐帧姿态与共享高斯的输入约定

这是本地序列适配的输入检查，不是官方完整复现，也不是训练质量通过证明。当前已有静态训练入口和保护不变。

## 运行检查

```bash
python scripts/check_frame_pose_inputs.py /path/to/frame-pose-manifest.json
```

退出码 0 只表示输入身份、文件和坐标格式检查通过。结果中的 `training_admitted` 和 `physical_calibration_validated` 仍为 `false`。退出码 2 时先修正输入与来源，不能跳过检查启动训练。

## 每帧必须能唯一对应

采用 `sequence_id` 和原视频 SHA256 区分视频。`frame` 是明确的字符串帧 ID，`source_frame` 是原视频帧号。图像、遮罩、完整 K、world-to-camera 外参和人体网格必须来自同一帧；不通过文件名排序或数组行号猜测。

相机记录和网格数组可使用不同顺序，加载后通过帧 ID 连接。二者必须覆盖完全相同的集合；缺失、重复、跨视频、图像哈希或相机不一致都会失败。最终用 `reference_frame_id` 指定输出姿态，不能默认第零帧。

Manifest 格式为 `shuolee-frame-pose/1`，字段包括：

| 字段 | 内容 |
|---|---|
| `purpose` | `real` 或 `synthetic_contract_test` |
| `sequence_id`、`video_sha256` | 视频身份 |
| `coordinate_system` | `opencv_world_meters`；OpenCV 相机方向，世界坐标单位米 |
| `pixel_domain` | `rectified_pinhole`；已有视频不二次去畸变 |
| `pixel_convention` | `integer_centers`；左上像素中心为 (0,0) |
| `reference_frame_id` | 必须存在的帧 ID |
| `frames` | JSON 的 `path`、`sha256` 和 `rows_key: records` |
| `poses` | NPZ 的 `path`、`sha256` |

两个描述文件相对 manifest 解析路径；每行图像和遮罩相对 frames JSON 解析路径，也支持绝对路径。

每行必须有 `frame`、`source_frame`、`sequence_id`、`video_sha256`、`wh`、`image`、`source_sha256`、`mask`、`mask_sha256`、`K_integer_centers`、`w2c`。文件哈希与图像实际宽高必须一致；图像与遮罩必须可完整解码，不能只读取文件头。

NPZ 禁用 pickle，要求 `frame_ids`、`source_frames`、`image_sha256`、标量 `sequence_id`/`video_sha256`、`vertices_world`、公共 `faces`、`shared_betas`、`K_integer_centers`、`w2c`。共享体型是 `(1,10)`，不是逐帧体型；世界网格是 `(帧数,顶点数,3)`。保存拟合快照时应直接保留相机与帧身份，不补造缺失信息。

## 像素与渲染器

接口内部使用完整整数中心 K，保留偏心主点和 skew。按实际整数输出尺寸缩放：`u'=(u+0.5)*sx-0.5`，`v'=(v+0.5)*sy-0.5`。

输出另提供 `K_renderer_corners`：在缩放后的整数中心 K 的主点加 0.5，只做一次。旧训练的 `row.K` 原本就是这种角点约定，因此其纯比例缩放不能单独作为错误证据。

旧 `CameraProj2` 不支持非零 skew，不能静默丢掉 skew。本接口只输出明确标注的数据；渲染后端连接、实际投影和像素回读还需单独验证。

## 逐帧训练和衣物点仍需完成的部分

后续训练必须保持一个共享高斯场和同一个优化器，在每次训练及评估渲染前选择相应人体姿态，最后从同一高斯场导出指定参考姿态。

已有网格相对运输可作为组件，但不能直接用其逐三角面配额与裸身体约束替换自由衣物表面点。新的运输应保留衣物位置和可学习偏移，并单独验证协方差、SH 坐标约定及参考姿态回读。

检查格式不证明相机准确、材料对应可靠或人物几何合格。当前实拍拟合失败记录保持不变；只有独立面部、全身和背景验收通过后才进入新的真实训练。
