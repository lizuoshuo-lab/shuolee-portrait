# smpl-x 历史 main 分支流程

本文保留 2026-10-28 旧 `main` 分支的部署与验证记录，用于追溯旧运行。下文中的 1200 步人体拟合、静态自由世界点、21 项模型资源及当时的部署命令，不适用于当前 `smplx/reconstruction` 开发分支。

当前部署和训练命令见 [README](../README.md)，资源清单见 [模型说明](models.md)。当前默认流程使用官方 SMPLify-X 逐帧拟合、按帧名匹配姿态与相机的高斯训练，以及指定参考姿态的通用导出。共享顶点偏移仍是尚未纳入部署默认配置的研究候选；其 18000 步实验完成不代表画质、新视频端到端、服务器或 15 分钟目标通过验收。

## 历史部署记录

按根目录README的一行命令部署，然后上传视频到 `~/smpl-x/videos/`。部署自动检测systemd：可用时安装 `smpl-x` 服务并开机启动；不可用时以当前用户启动独立后台进程，不需要sudo或保持终端连接。

公开仓库的部署分支为 `main`，下载不需要GitHub登录。如果先前克隆因用户名读取失败而退出，可以直接重新执行README中的命令；Git会清理未完成的目标目录。

如果已经克隆成功、仅部署报错，用下面一行更新并重新部署。它也会恢复旧版Git稀疏检出遗漏的根目录入口和依赖文件，不重复克隆：

```bash
git -C ~/smpl-x/app sparse-checkout init --cone && git -C ~/smpl-x/app sparse-checkout set && git -C ~/smpl-x/app pull --ff-only && bash ~/smpl-x/app/deploy.sh
```

## 输入和结果

支持MP4、MOV、MKV、AVI、M4V、WEBM，直接放在视频文件夹内。WinSCP保持默认临时文件上传方式：`.filepart`文件会被忽略，上传完成后自动恢复原文件名。程序等文件大小及修改时间稳定30秒后保存独立输入快照，原上传文件保持原样。不要在上传到最终视频文件名的过程中暂停超过30秒。

多个视频按入队顺序串行运行；内容哈希防止重复上传或改名后重复训练。文件内容改变会建立新任务。任务记录在 `queue/jobs/`，日志在 `queue/logs/`，运行在 `runs/`。这些目录与模型、Python环境均在Git外。

完成重建的运行导出：

- `export/point_cloud.ply`：Graphdeco标准3DGS，完整SH、log-scale、logit-opacity和wxyz旋转。
- `export/cameras.json`：通用3DGS相机，完整fx/fy/cx/cy及相机到世界旋转。
- `export/colmap/`：COLMAP PINHOLE文本相机；没有伪造稀疏点和图像观测。
- `export/validation.json`、`camera_provenance.json`：数值一致性和坐标来源。

## 固定流程

每5帧采样，最长边1600，12–300帧；人体拟合1200步；20万初始点；18000训练步；种子6060。高斯使用自由世界坐标，人体只提供本轮初始化范围和尺度。每轮从原视频重新估计相机、人物参数和优化器，不读旧人物结果。

输入完整性、拟合误差、轮廓体积、有限数值、点数预算和原生/PLY渲染一致性自动检查。异常保留具体错误，队列继续下一个视频。失败或被中断的任务保留现场，不无限重试；重启不会覆盖已有训练或把未完成任务报告为成功。完成状态表示流程完成，物理几何精度另由测量确定，没有人工审批步骤。

默认相机前端保留原流程的标定处理：使用现有MONO_MAIN_MFR第一组4000×3000内参，根据视频实际宽高换算下采样、居中裁剪和抽帧缩放。横屏裁去上下区域，竖屏裁去左右区域，保留各自fx/fy与主点；不用交换横竖轴，也不重新估焦或再次去畸变。新图像SIFT轨迹用于Essential/PnP和固定K束调整。该默认相机配置针对当前采集设备的已去畸变视频，不能自动代表其他设备；精确整数裁剪位置和物理精度仍未独立测量。遮挡、微动、低纹理会影响结果。保留原有轮廓计票方式及出画面区域计负证据的限制。

相机特征提取前，用固定版本YOLO在完整画面检测全部人物，并排除外扩8%的检测框。未检测到人物的帧不用于相机求解；剩余背景仍需几何验证，检测框不能证明整个背景静止。相机求解完成后再生成用于人体拟合的SAM2遮罩和RTMW观测。人物保持姿势、相机绕拍是当前静态重建的输入条件。

## 恢复和结果反馈

每个队列任务结束后写入 `queue/results/<内容标识>.json`。`python3 ~/smpl-x/app/watch.py --status` 显示中文结果，不加载CUDA、不启动训练。内部进程仍保留真实退出码和技术状态；用户结果包含 `outcome`、`code`、`message`、`actions`、`model_available` 和日志位置。仅完整18000步及导出完整性检查通过时提供模型。

| 条件 | 自动处理 | 最终反馈 |
| --- | --- | --- |
| 少量低纹理、未注册或观测不足的帧 | 保留至少12帧和90%的采样帧，连续缺帧最多2帧；重新统一相机、原始帧编号和人物观测顺序 | 完成时说明跳过的帧数；超过范围则提示补拍 |
| 全局选点导致某些相机缺少观测 | 先为各相机保留至少50个已验证观测，再按轨迹长度填满5000点预算 | 保存逐帧可用与选中观测数；无法满足时反馈相机求解不足 |
| 无有效背景、无法初始化相机、人物观测不稳定 | 保存诊断，结束当前任务并继续队列 | `needs_recapture`，说明限制及拍摄建议 |
| 内存不足、相机计算超时、依赖异常、数值或导出检查失败 | 保留原视频、运行数据和日志，继续队列 | `system_error`，说明检查方向 |
| 进程被信号终止、工作进程重启 | 收集退出码；重启后补齐结果，等待仍存活的子进程退出 | 强制终止原因未明时不推断OOM；主动中断为 `interrupted` |

恢复只使用已求出的真实相机，缺失帧不插值。数值和导出检查保持有效。旧的失败任务会补齐可读反馈，但不会仅因部署更新而重复训练。真实视频在新前端下的验证与旧版本完整训练记录分别记录，见 `provenance/deployment-validation.json`。

## 维护

日常只需上传视频。部署成功会输出 `smpl-x READY`、启动方式和状态路径。systemd方式可用 `systemctl status smpl-x` 和 `journalctl -u smpl-x -n 80`；后台方式的进程日志在 `~/smpl-x/queue/worker.log`。两种方式共用 `queue/status.json`；具体阶段和原始错误在运行目录的 `status.json` 与队列任务日志内。

后台方式在机器或容器重启后需再次运行 `bash ~/smpl-x/app/deploy.sh`。重复部署会核实并复用已运行的进程；退出SSH/WinSCP不会停止接收视频。工作进程异常退出时，仍存活的训练子进程持有队列锁；重启还会检查原训练进程组，避免同时启动第二份训练。中断的任务保留结果，不自动重训。

Git更新应在队列空闲时进行：停止服务，`git pull --ff-only`，再运行 `bash deploy.sh`。后台方式可向状态文件中核实属于本项目的工作进程PID发送SIGTERM，等状态变为 `stopped` 后更新。不会覆盖已有结果。部署目录已存在时直接运行其 `deploy.sh`，不重复克隆。

自定义路径只需首次部署前设置环境变量：`SMPLX_ROOT`改变videos/runs/queue的共同父目录；`SMPLX_ENV_DIR`指定隔离Python环境；`SMPLX_ASSETS`指定已有模型来源目录。部署优先复用完整目录；旧113目录缺少的公开依赖自动下载并组装到 `SMPLX_ROOT/models`，原目录保持不变。下载中断后再次部署会继续下载，完成后校验全部21个文件，再检查CUDA前向/反向。服务以部署用户身份运行，配置记录于 `queue/deployment.json`。

本地验证记录于 `provenance/deployment-validation.json`，分开记录真实视频完整训练、文件夹触发、CPU队列测试、GPU环境复用和目标服务器部署状态。

2026-10-28本地实测：00数据集的5段横屏和3段竖屏视频均通过格式检查与实际抽帧，覆盖8位和10位HEVC。横屏按1600×899、竖屏按899×1600处理。恢复原流程的已有标定映射后，横屏89帧、竖屏112帧各自从原视频完成1200步拟合、18000步训练和通用导出；独立plyfile与pycolmap读取通过，完整内参得到保留。两次运行均未复用旧人物、相机或优化器。临时上传文件被忽略，服务重启后仍只有两个完成任务。本地复用已有CUDA环境，尚未验证全新系统安装或在00/113服务器部署；流程通过不代表独立物理精度已测定。先前自动估焦导致竖屏失败的记录保留在验证文件中。
