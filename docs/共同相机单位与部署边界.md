# 共同相机单位：CPU部署与验证

这是逐帧接口的单位保护增量，尚未完成真实人物训练。

## 已验证

输入必须声明相机平移单位、共同正比例、依据和证据。相机平移统一到人体模型米制后再进行相机到世界变换；旋转和内参不变。任何额外SfM点也必须使用同一比例。

检查点保存单位来源、帧顺序和冻结相机。缺失或冲突必须拒绝加载，包括嵌套模块和非严格加载。

## 运行

使用已有 Python 3.10、NumPy 1.26.4、PyTorch 2.7.1 环境；CPU 即可，无需下载 SMPL-X、VPoser 权重或编译 CUDA。旧 PyTorch 1.12 不支持本检查使用的 `weights_only=True` 安全加载，不能取消该选项来绕过。

在已有部署环境的 Linux 服务器执行下面一条命令：独立检出本分支，复用现有 Python 并运行 CPU 单位检查。目录已存在时停止，不覆盖旧部署。

```bash
bash -c 'set -eu; test ! -e "$HOME/smpl-x-world-units"; git clone --depth 1 --filter=blob:none --no-checkout --branch smplx/world-units-contract-123 https://github.com/lizuoshuo-lab/shuolee-portrait.git "$HOME/smpl-x-world-units"; cd "$HOME/smpl-x-world-units"; git sparse-checkout init --cone; git checkout; git sparse-checkout set src scripts tests docs; CHECK_PY="${SMPLX_ENV_DIR:-$HOME/.local/share/smpl-x/env-cu128}/bin/python"; if [ ! -x "$CHECK_PY" ] && [ -z "${SMPLX_ENV_DIR:-}" ]; then CHECK_PY="$HOME/.local/share/shuolee-portrait/env-cu128/bin/python"; fi; test -x "$CHECK_PY"; export CUDA_VISIBLE_DEVICES=""; mkdir -p test-results; git rev-parse HEAD; "$CHECK_PY" -s -B tests/test_camera_world_units.py --report test-results/world-units-cpu.json'
```

已有代码目录可直接运行：

```bash
CUDA_VISIBLE_DEVICES='' python -B tests/test_camera_world_units.py --report test-results/world-units-cpu.json
```

25 项检查必须全部通过。报告中的合成尺度 0.4 是已知几何控制，绝不能作为真实视频参数。

CI 使用 `requirements-test.txt` 中固定的 PyTorch `2.7.1+cpu`，完整运行新增检查和原有回归。新建的独立 CPU 测试环境可安装此文件；已有 CUDA 运行环境只运行检查，避免用测试依赖替换生产环境。

相机内参作为固定输入，不接收梯度。相机及帧顺序在投影、坐标转换和快照输出时重新检查；快照保存完整帧 ID。浮点精度应在构造时通过 `dtype` 选择，构造后改变精度会被拒绝，原始外参始终保留 float64。

## 仍未解决

实际视频共同尺度与物理标定、真实逐帧数据准入、自由衣物高斯姿态运输和完整渲染连接仍待验证。历史拟合尺度不是已验证标定，不自动复用。不能对已经混合单位生成的网格整体乘一个比例冒充修复。

`evidence` 只记录非空的来源说明；`model_conditioned` 只声明估计依据。两者均不证明物理尺度、共同 SfM 基准或训练准入。旧静态拟合已有尺度处理，本次发现不能解释为所有历史重影的唯一原因。

只部署本包模块和测试，不执行旧拟合脚本；旧脚本没有传递新单位声明，且部分旧脚本在构造模块之前会加载模型。未来运行入口必须先检查单位与数据，再加载任何模型或启动GPU。

本接口是本地逐帧适配实现，不是SMPLify-X或GaussianAvatars_SMPLX完整官方复现。
