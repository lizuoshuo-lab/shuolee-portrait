# 同相机地图评测：覆盖如何改变误差指标

十二份 V4 最终地图在相同的后续十帧已知相机下完成了 120 次渲染。desk 先验组的颜色和覆盖内深度误差改善，但含孔洞误差变差；xyz 在两组共同覆盖的相同像素上，三个种子的深度 RMSE 均略变差。轨迹修正变稳定，没有自动带来全面更好的地图。

## 只评地图，不优化相机

本实验读取 desk/xyz、seed 0/1/2、λ=0/0.01 的十二份已完成 `last_checkpoint.pt`。这些地图只用关联帧 200–299 训练；评测固定为 300–309。RGB/深度的路径与索引均不复用，高斯来源 ID 均属于训练帧。CPU 协议记录实际输入、相机、参数及文件 hash，在 GPU 开始前已冻结。

每个评测相机使用 `c2w_relative = inverse(GT_c2w_200) @ GT_c2w_eval`，与训练首相机 identity 的世界约定一致。地图不做 SE3/Sim3 拟合或变换，相机不接受梯度，模型参数也不更新。GT 在这里明确提供评测相机；这回答“地图在给定参考相机下怎样渲染”，不能作为跟踪或定位精度指标。

仍使用原 V4 的 `RGB+ED` 渲染函数、160×120、黑色背景、0.1–6m 渲染裁剪与 0.2–5m 传感器有效深度。训练器 SHA256 保持 `ee7e28700b489a12208006c7c7cc407dbd9af9ab655d0d310f5dde8e7ef4506f`。没有增加训练、挑选种子、改变 alpha 阈值或用 GT 调参。

300–309 虽未进入这些地图的训练，仍来自同一序列和传感器域，是诊断性后续帧验证，不能称为全新场景或未参与研究决策的最终测试集。GT 使用最近 RGB 时刻的样本，不插值，RGB/深度时间差未补偿；内参和已注册 RGB-D 仍采用 Freiburg1 的读取约定。

## 四个指标的分母

设传感器有效像素集合为 V，预测期望深度为 d，传感器参考深度为 z。每个地图自身覆盖集合为 `C = V ∩ {alpha > 0.5} ∩ {finite(d), d > 0}`，阈值严格大于 0.5。

| 指标 | 使用的像素 | 它回答的问题 |
| --- | --- | --- |
| RGB PSNR | 全图全部 RGB 通道，包含黑色背景 | 整张预测图与观测颜色有多接近 |
| 覆盖率 | `count(C) / count(V)` | 有效传感器像素中多少有地图覆盖 |
| 自身覆盖深度 RMSE | C | 各地图满足覆盖条件的区域内，深度误差多大 |
| 含孔洞深度 RMSE | V；C 外预测置 0 | 固定有效传感器分母，同时惩罚未覆盖区域 |

两组比较还报告共同集合 `C_common=C_off∩C_on` 的 RMSE，让两组使用完全相同的参考像素。它仍排除两组都未覆盖及只被一组覆盖的区域，不能替代全有效像素评测。

每份地图先汇总十帧的 SSE 和实际像素数，再计算 pooled MSE/RMSE/PSNR；下表再对三个种子的地图指标取均值 ± 样本标准差。它不是先对十帧 PSNR 求均值，也不是把三种子所有像素一次池化。两种口径都在原指标中保留，不能混用。

## 覆盖增加，为什么含孔洞误差仍会增加

覆盖率只统计数量，不区分哪些像素被补上、哪些像素变成孔洞。为精确核对这个差别，把同一份传感器有效集合 V 分成四个互斥组。令 off 为 λ=0、on 为 λ=0.01，`e_off=d_off-z`、`e_on=d_on-z`，z 始终是观测 RGB-D 的参考深度：

```text
共同覆盖：C_off ∩ C_on             ΔSSE_common = Σ(e_on² - e_off²)
新增覆盖：C_on \ C_off             ΔSSE_new    = Σ(e_on² - z²)
丢失覆盖：C_off \ C_on             ΔSSE_lost   = Σ(z² - e_off²)
始终未覆盖：V \ (C_off ∪ C_on)    ΔSSE_never  = 0

SSE_on - SSE_off = ΔSSE_common + ΔSSE_new + ΔSSE_lost + ΔSSE_never
ΔMSE = (SSE_on - SSE_off) / |V|
ΔRMSE = sqrt(SSE_on / |V|) - sqrt(SSE_off / |V|)
```

SSE 和相同分母下的 MSE 差可以逐组相加，RMSE 差不能。新增覆盖是在原来的零深度惩罚 `z²` 上换成渲染残差；丢失覆盖则反过来。因此，孔洞处的传感器深度及原有残差，与孔洞数量同样影响这个指标。

以 desk、seed 0 的十帧 pooled 结果为例，`|V|=136145`。下表计数是**像素观测（帧×像素）**，不是独立物理点的数量。每项 ΔMSE 都除以同一个 136145：

| 区域 | 像素观测数 | 传感器深度均值 m | 对 ΔMSE 的贡献 m² |
| --- | ---: | ---: | ---: |
| 共同覆盖 | 80178 | 1.796591 | −0.03909381 |
| 新增覆盖 | 12254 | 2.100768 | −0.41298794 |
| 丢失覆盖 | 11585 | 2.483758 | +0.51824097 |
| 始终未覆盖 | 32128 | 2.716999 | 0 |

新增覆盖比丢失覆盖多 **669** 个像素观测，但丢失覆盖项的误差增量超过另外两项的改善，合计 **ΔMSE=+0.06615922m²**，对应含孔洞 RMSE 从 1.521335m 升至 1.542925m。丢失组的平均参考深度更大，是理解这份零深度惩罚的一个具体线索；精确结论依据的是整组 `Σz²` 与残差平方和，不能只比较深度均值就推出误差变化。

始终未覆盖组的“差为 0”也不表示没有误差：这组在两张地图中都按零预测，双方各贡献 **239494.060344m²** 的 SSE，只是在求差时完全抵消。

| --- | ---: | ---: | ---: | ---: |
| desk / 0 | −0.03909381 | −0.41298794 | +0.51824097 | +0.06615922 |
| desk / 1 | −0.03420875 | −0.40059041 | +0.50208229 | +0.06728312 |
| desk / 2 | −0.03500383 | −0.41587045 | +0.50574391 | +0.05486962 |
| xyz / 0 | +0.00049111 | −0.01087138 | +0.01008333 | −0.00029694 |

图中两个序列共用纵轴尺度；正值增加误差，负值减少误差，黑菱形是代数总和，不是不确定性误差条。xyz 的变化在这把共同尺度上较小，精确值见表及原始记录；不能将不同分母的 SSE 大小直接跨序列比较。

[完整分解](../outputs/tum-v4-coverage-sse-decomposition-001/decomposition.json)保留全部六对地图、60 对帧、120 份预测来源，以及每组像素数、参考深度均值、深度平方和、双方 SSE 和实际 mask hash。[CPU 核对](../outputs/tum-v4-coverage-sse-decomposition-001/validation.json)完成 336 次标量比较，分组和与原含孔洞 SSE、`MSE×N` 一致，最大差约 `6.18×10⁻¹¹m²`。该[分解源码](../scripts/decompose_tum_v4_coverage_sse.py)只读取已有 NPZ 与冻结 loader，不调用 GPU，不重新渲染，不改变阈值。

这是一份对**同一 RGB-D 传感器参考**的误差组成核对，不把参考深度当作无误差的真实表面，也不唯一确定地图缺失来自哪个物理或优化环节。它说明了当前指标为何变化，不能替代对位姿、覆盖形成过程和几何一致性的进一步验证。

## 可复核记录与适用范围

[冻结 CPU 协议](../outputs/tum-v4-final-map-future10-cpu-check-003/protocol.json)记录十二份实际 checkpoint SHA 和十帧输入；[评测源码](../scripts/evaluate_tum_v4_final_maps.py)仅抽取原 V4 渲染 AST，使用 `torch.no_grad()`，检查上传前后参数字节及原 checkpoint 字节不变。整个 GPU 分支渲染与导出耗时约 9.66 秒，不作为完整 SLAM FPS。

[统一摘要](../outputs/tum-v4-final-map-future10-summary-001/summary.json)保留每份地图、每帧、六对共同覆盖比较、不同聚合方式与所有种子；[摘要核对](../outputs/tum-v4-final-map-future10-summary-001/validation.json)与[独立产物审计](../outputs/tum-v4-final-map-future10-001/independent_map_quality_audit.json)均通过。独审不调用原指标函数、不重新渲染：从实际 PNG 独立读取 RGB/255、深度/5000，核对全部输入与 120 NPZ 的 360 个预测数组 hash，另用 xyzw 旋转与解析刚体求逆验证相机方向。

120 次单帧指标、12 份地图汇总与 60 次共同覆盖指标均重新计算，最大标量差约 `5.82×10⁻¹¹`，来自大 SSE 累加舍入；这个最大差跨不同量纲字段，不能统一称为米。全部十二地图、120 渲染与六对十帧比较完成，没有用零误差填补缺失结果。

源码另见[只读汇总与诊断图](../scripts/summarize_tum_v4_final_maps.py)和[独立地图评测审计](../scripts/audit_v4_final_map_quality.py)。原模型、预测 NPZ 与全部原始记录留在本地；本实验是已知相机地图质量检查，完整 SLAM 仍需要另外验证定位、回环、重定位和全局一致性。
