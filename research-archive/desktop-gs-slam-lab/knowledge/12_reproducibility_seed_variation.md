# 12 随机种子、GPU 非确定性与重复实验

固定随机种子（random seed）是控制实验的一部分，但它既不保证 GPU 输出逐字节相同，也不保证方法在另一种初始化、另一条序列上有效。判断实验能否复核，需要同时说清楚随机状态、实际输入、计算实现、评测单位和失败处理。

复现要区分随机抽样、计算确定性和结果稳健性。seed 控制随机生成器起点；实际输入状态决定优化问题；重复与换场景才检验结论对扰动是否稳定。

## 随机种子与伪随机数状态

伪随机数生成器根据内部状态产生序列。设置 seed 相当于给某个生成器一个起点；只有后续调用方式、调用顺序和随机数消耗一致，才有理由期待相同的随机抽样。模型结构、张量形状或多进程调度改变后，“写了同一个整数”本身并不证明实际初始化一致。

Python、NumPy 与 PyTorch 各自管理随机状态：

| 设置 | 控制范围 | 容易遗漏的部分 |
| --- | --- | --- |
| random.seed(seed) | Python 模块级随机生成器 | 独立创建的 random.Random 对象有自己的状态 |
| np.random.seed(seed) | NumPy 旧式全局随机状态 | np.random.default_rng(...) 创建的 Generator 不由这次设置统一控制 |
| np.random.default_rng(seed) | 返回的那个 NumPy Generator | 别的 Generator、后续调用顺序和抽样数量 |
| torch.manual_seed(seed) | PyTorch 的 CPU 与 CUDA 随机生成器 | Python、NumPy、其他库的随机源，以及不由随机数引起的计算非确定性 |

例如，[Tiny NeRF 教学脚本](../scripts/train_tiny_gs.py)用 torch.rand(N, 3, device='cuda') 初始化中心，再用 Python 的 random.choice(train_indices) 选训练视角。两个随机源分别设种子。4000 与 8000 个高斯可以使用相同的视角抽样顺序，但不能据此声称它们的高斯初值逐粒一一对应，或 8000 组只是给 4000 组附加了另一半高斯。

[TUM loader](../scripts/tum_rgbd.py)的深度点抽样使用显式 np.random.default_rng(seed)；[V4 训练器](../scripts/train_tum_online_gs_v4.py)还设置 Python、NumPy 全局与 PyTorch 的种子。这说明复核时要检查实际调用路径，不能只搜索一次 manual_seed 就宣布所有随机性已受控。若使用多进程 DataLoader，还需要按其实际 worker 与 generator 配置核对状态；本地这些教学脚本的逐帧读取不能直接代表多进程加载场景。


## 相同随机抽样为什么仍可能得到不同数值

浮点加法不满足实数意义上的结合律：$\operatorname{fl}(\operatorname{fl}(a+b)+c)$ 与 $\operatorname{fl}(a+\operatorname{fl}(b+c))$ 可能因为舍入得到不同结果。$\operatorname{fl}$ 表示浮点运算结果。某些 GPU 并行归约或原子累加的求和顺序不固定，即使输入字节相同，也可能出现数值差异。迭代优化又会把微小差异传到后续梯度、可见性、排序、阈值 mask 和最佳候选选择。

这是一般机制说明，不是对本实验差异来源的唯一诊断。PyTorch 的官方复现说明明确指出，不同版本、提交、平台以及 CPU/GPU 之间不保证完全复现。第三方 CUDA 扩展的确定性还要单独核对；不能仅凭 torch.use_deterministic_algorithms(True) 就断言 gsplat 的所有自定义核均得到保证。该开关可能换用受支持的确定性实现，也可能对不支持的操作报错；它不等于固定 seed，更不等于跨环境逐位保证。


## 比预设更强的控制：固定实际张量


“固定初始化”也必须说明具体固定了什么。若比较从零开始的优化，应核对初始参数、观测、相机、参考、随机状态和优化器初始状态；若比较中途恢复，还要包括 Adam 动量、步数、学习率调度器等状态。只保存模型参数、却让两个运行从不同优化器历史继续，并不是相同训练起点。

对于不同高斯数量、不同网络结构等无法逐张量匹配的方案，可以配对数据划分、观测顺序和种子，并公开哪些状态无法相同；不能把这种配对描述成实际张量完全一致。

## 均值和样本标准差测量什么

令 $x_i$ 为第 i 次完整运行采用相同聚合规则得到的指标，共 $n$ 次：

$$
\overline x=\frac1n\sum_{i=1}^{n}x_i,\qquad
s^2=\frac1{n-1}\sum_{i=1}^{n}(x_i-\overline x)^2,\qquad
s=\sqrt{s^2},\qquad n\geq2.
$$

$x_i$ 为第 $i$ 次完整运行的指标，$\overline x,s$ 与该指标同单位；$s^2$ 为对应单位的平方。

这里 $s$ 描述运行指标的离散程度，不是帧间标准差、标准误或置信区间。$n$=1 不能给出种子间样本标准差；小标准差也不代表小偏差。样本方差采用一个自由度校正，不自动建立独立同分布（independent and identically distributed，IID）假设，连续帧和共享场景尤其不能当作独立重复。

PSNR 先取对数后按视角平均，与先汇总像素 MSE 再换算不同。比较时固定聚合方法；用来选择方案的验证视角不能再称为未参与选择的最终测试集。

## 同种子重跑与更换种子回答不同问题

| 控制方式 | 主要问题 | 不能单独推出 |
| --- | --- | --- |
| 同配置、同 seed 重复执行 | 固定随机设定下，当前实现与运行环境的输出波动多大 | 对其他初始化是否稳健 |
| 同配置、更换 seed | 结果对初始化、抽样等随机选择有多敏感 | 同 seed 的计算是否逐位确定，或能否跨场景泛化 |
| 相同实际上下文，仅改变一个目标项 | 固定当前地图和观测时，局部优化机制怎样变化 | 完整在线地图历史中的稳定收益 |
| 固定配置、换序列 | 相同规则在另一个数据序列上的表现 | 来自不同传感器或不同场景分布的普遍性能 |

换种子运行通常同时包含种子间差异和运行内数值波动。若没有同种子的重复运行，就不能从种子间标准差中把这两者分离。独立设置几个随机源也不意味着评测样本 IID：运行共享数据、实现和系统性误差；连续轨迹的相邻帧更不是互相独立的实验。


## 把运行失败与帧失败分别保留

一次进程未完成、一次完整运行内有拒绝帧、一个完整运行精度较差，是不同状态。报告应保留尝试次数、完整结果数、不完整运行数与原因，再说明使用了哪些结果计算均值。不能把无指标的运行填成零误差，也不能删除失败记录后只展示成功样本的均值。

例如当前 ICP/GS 原型的拒绝帧会保留在轨迹中，并传播上一估计；最终误差统计也保留这些帧。[V3 20 帧 refinement](../experiments/2026-10-09-icp-initialization.md)虽记录了完整轨迹，却有首次梯度检查失败与回退。因此“程序完成”不等于“每帧检查通过”，而“0 flags”又不等于定位准确或每层都已收敛。

帧拒绝率与运行失败率分别为：

$$
f_{\mathrm{frame}}=\frac{N_{\mathrm{rejected\ frames}}}{N_{\mathrm{eligible\ frames}}},
\qquad
f_{\mathrm{run}}=\frac{N_{\mathrm{failed\ runs}}}{N_{\mathrm{attempted\ runs}}}.
$$

两种分母都必须大于零，未完成但仍在运行的尝试应另列数量与状态，不能计为已经确认的失败。

帧失败率需要写清分母是否排除固定首帧，运行失败率则以实际尝试的运行数为分母。尚未结束的运行应单列 pending，不能混入已确认的失败。若只对完整运行计算指标均值，应明确它是对完整运行的条件统计，不能遮蔽不完整运行的比例与原因。

可复核的结论最终依赖一组相互对应的证据：代码和环境版本、配置、数据划分与关联、随机状态、必要的实际张量、完整状态和失败记录，以及定义一致的指标。seed 是其中一个字段。

## 重启与失败分母

从头重跑是一项新的尝试，不能覆盖原失败记录；从 checkpoint 恢复则要包含优化器、随机源和调度器状态。报告实际尝试数、完整结果数、不完整结果和原因，说明均值是否仅对完整运行计算。重跑成功不能倒推出历史故障的唯一根因。

## 实验附录

以下为对应教学实现的历史实测与核验，供查证具体数据及适用范围。

本地已有三类证据：同 seed 的独立 warmup 地图不同；固定实际张量的单帧回放仍未逐位复现原输出；Tiny NeRF 高斯数量对照完成了三个种子的统计。这三类实验回答不同问题，不能互相替代。

### 实测：相同 seed 的两份 warmup 地图并不相同

以下两组流程都使用 seed 0，首帧 warmup 150 步。每组内部的初始传感器、K、ICP 初值与先验参考张量相同，但五组 warmup 高斯参数均不是逐字节相同。

| 同一片段的两轮运行 | `means` 最大单元素差 | 同索引中心三维距离最大值 | 中心三维距离 RMS |
| --- | ---: | ---: | ---: |
| desk，λ=0 与 0.01 | 31.748 mm | 47.843 mm | 3.673 mm |
| xyz，λ=0 与 0.01 | 84.772 mm | 99.437 mm | 3.610 mm |

数值来自 [desk 比较](../outputs/tum-online-v4-prior-comparison-001/comparison.json)与 [xyz 比较](../outputs/tum-xyz-online-v4-comparison-001/comparison.json)。最大单元素差取所有高斯的某个 x、y 或 z 分量；三维距离则是每个高斯中心差向量的二范数。这两个“最大值”不能混用。这里比较的是两次优化后参数的差异，不是对真实表面的重建误差；四元数等其他参数的元素差也不能直接当成几何角度误差。

两个流程后来还会使用各自的地图历史，所以完整轨迹差值包含首次地图差异和后续建图反馈。相同配置预设下的运行仍然有比较价值，但它不是“输入地图完全相同，只改变一个损失项”的严格状态控制。

### 实测：三个种子的均值和样本标准差

已完成的 [Tiny NeRF 数量对照](../experiments/2026-10-08-gaussian-count-study.md)使用同一 Lego 数据、已知相机、100×100 图像、100 个训练视角和 6 个验证视角，每次优化 1500 步。以下每个单元格是一个种子的六视角 PSNR 算术均值，单位都是 dB：

| 高斯数量 | seed 0 | seed 1 | seed 2 | 三个种子均值 ± 样本标准差 |
| --- | ---: | ---: | ---: | ---: |
| 4000 | 26.862957 | 26.890624 | 26.778372 | 26.843984 ± 0.058482 |
| 8000 | 27.496563 | 27.388826 | 27.345854 | 27.410414 ± 0.077639 |

[统计 JSON](../outputs/gaussian-count-study-001/metrics.json)保留六项原始运行来源；[产物检查](../outputs/gaussian-count-study-001/validation.json)确认参数有限、高斯数量与划分正确。8000/seed 0 复用此前完成的结果，另五项分别运行；不是对 seed 0 重新执行了一次。同种子 8000−4000 的差值分别为 `+0.633606、+0.498202、+0.567482 dB`。

令 `x_i` 表示第 i 个种子的六视角平均 PSNR，则本表使用：

```text
mean = (x_1 + ... + x_n) / n
s²   = Σ_i (x_i - mean)² / (n - 1)
s    = sqrt(s²)                         n ≥ 2

numpy.std(seed_means, ddof=1)            # 分母 n-1；这里 n=3
```

这份标准差描述三个种子均值之间的离散程度，不是六个视角之间的标准差，不是标准误，也不是置信区间。`ddof=1` 只规定分母；在相应抽样假设下，它使样本方差成为总体方差的无偏估计，并不使开平方后的标准差自动无偏，更不会自动建立 IID 假设。只有一个运行时，不能用 `ddof=1` 得到有意义的种子间样本标准差。

PSNR 本身是对 MSE 取对数后的指标。先对各视角 PSNR 求均值，与先汇总所有像素的 MSE 再换算 PSNR，通常不是同一个量。不能混合两种聚合方式后比较均值或标准差。

这些六视角已经用于比较高斯数量，当前角色是探索性验证；原 JSON 字段名中的 `test` 不会让它重新变成未参与决策的最终测试集。三个种子也仍共享同一小场景和相机集合。三项差值都为正，是这组已完成实验的描述，不能单凭它宣称统计显著、样本 IID 或通用泛化。

这条 loader 路径始终调用 `rng.choice(..., replace=False)`，并不是给深度反投影的中心额外添加随机扰动。已完成 V4 的首帧记录中，desk 有 12108 个有效候选，少于 15000 上限，因此全选，换 seed 改变的是点的排列，物理像素集合不变；xyz 有 15037 个候选而只选 15000 个，换 seed 会改变子集与排列。点顺序仍可能影响后续并行数值计算。这是两条序列不同的随机化机制，不能把它们统一解释成“每个种子都有不同的物理初始点集”。

本地已有实验没有为了消除观察到的差异而修改锁定的 CUDA 确定性配置。因此记录代码和依赖版本、输入 hash、实际输出与容差，比仅保留 seed 更有解释力。

[单帧先验回放](../experiments/2026-10-09-fixed-context-prior.md)直接复用保存的 desk 首次 tracking 上下文：同一份 warmup 地图、RGB-D、有效深度 mask、K、ICP 初值与参考，五组地图参数和七组输入张量都核对 hash。两组优化只改变先验权重，没有重新初始化、warmup 或建图。

即便如此，相同目标的 λ=0 回放候选，与原完整运行首次选中候选的中心仍相差约 **0.897 μm**，详见[事后分析](../outputs/tum-pose-prior-context-replay-001/analysis.json)。输入字节固定与输出逐位复现是不同要求。这个微小距离既不是精度收益，也不是某个核存在错误的证明；比较中仍需保留 GPU 潜在非确定性和额外诊断调用的边界。

[V4 两条序列的三种子复测](../experiments/2026-10-09-v4-seed-replication.md)现已完成：四份 seed 0 复用，另八份实际运行，每序列/权重共有三份完整轨迹。desk 先验组锚定位置 RMSE 为 `65.702±0.059mm`，xyz 为 `41.511±0.030mm`，`±` 均为种子间样本标准差。小标准差描述运行之间接近，不会把约 65.7mm 的偏差变成亚毫米准确度；也没有从种子间变化中分离 GPU 非确定性。原指标、每轮退出账本和独立统计审计相互对应。排队、正在运行或仅有配置的条目仍不能进入已完成均值。

#### 重启不会消除原来那次尝试

[完整序列 GS 对照](../experiments/2026-10-09-full-v4-sequence-controls.md)包含 5 次尝试、4 组完整结果和 1 次不完整运行。原第四次在保存进度时发生 Windows `PermissionError`，停在已处理 521 帧；随后在另一个目录按预先固定配置从第 0 帧重跑，没有从失败 checkpoint 恢复。原三组加显式重启组构成四个完整对照，原失败的 1,067 份文件与哈希仍被保留。不能将原批次的 `[0,0,0,1]` 退出码改写为四次成功，也不能把失败耗时排除后称为完整处理成本。

原子替换保证读者不看到一半新文件，并不保证任何平台上替换必定成功。Windows 上其他进程持有文件句柄时，实际共享方式可能阻止替换；因此训练监控优先读取小型追加日志和进程状态，避免长期打开频繁替换的大型进度文件。隔离控制复现了持有句柄时失败、关闭后成功，但没有定位历史错误的唯一持有者或证明其唯一原因；添加允许删除的共享标志在本机控制中也没有使替换成功。重跑完成只能证明这次执行完成，不能倒推原先的唯一故障根因。
